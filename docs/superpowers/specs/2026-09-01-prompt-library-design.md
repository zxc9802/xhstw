# P 页面提示词库设计

## 目标

在图片生成步骤的每个 P 页面提示词框旁提供同一个提示词库入口。用户可以在当前浏览器中长期保存常用提示词，并完成搜索、新增、编辑、删除和一键填入，减少重复输入。

## 范围

- 提示词库在所有 P 页面之间共用。
- 数据仅保存在当前浏览器，不上传服务器，也不进行账号间同步。
- 本次不增加分类、标签、排序、导入或导出功能。
- 提示词填入只作用于打开弹窗时对应的 P 页面。

## 入口与弹窗

- 每个 P 页面的“提示词”标题右侧显示“提示词库”按钮。
- 点击按钮打开居中弹窗，标题为“提示词库 · 填入 Pn”。
- 弹窗顶部提供关键词搜索和新增入口，主体显示提示词列表。
- 搜索实时匹配名称和完整提示词内容，忽略关键词首尾空格及英文大小写。
- 无提示词和无搜索结果分别显示明确的空状态。

## 提示词管理

每条提示词包含：

- 唯一 ID；
- 可选名称；
- 必填提示词内容；
- 创建时间；
- 更新时间。

新增或编辑时，名称可以为空，提示词内容去除首尾空格后不能为空。列表中没有名称的记录显示“未命名提示词”，并始终展示内容摘要。每条记录提供“使用”“编辑”“删除”操作；删除前需要用户确认。

## 填入规则

- 当前 P 的提示词框为空时，点击“使用”后直接填入并关闭弹窗。
- 当前 P 的提示词框已有非空内容时，先确认是否替换；确认后整段替换并关闭弹窗，取消则保持原内容和弹窗状态。

## 数据与组件边界

- 使用项目现有的版本化本地状态工具读写独立的 `localStorage` 键。
- 页面组件持有提示词库数据、当前目标 P 和弹窗开关状态。
- 新建独立的提示词库弹窗组件，负责搜索、表单、列表和管理操作；页面通过回调处理最终填入。
- 新建纯函数模块，集中定义提示词条目类型、输入校验、搜索与增删改操作，便于测试并保持页面改动集中。
- 新增、编辑和删除成功后立即尝试写入浏览器存储。

## 异常处理

- 本地存储内容缺失、版本不匹配或格式损坏时，以空提示词库启动。
- 浏览器拒绝写入或存储空间不足时，当前页面内的数据仍可继续使用，同时通过页面现有反馈区域提示“保存到浏览器失败”；不声称数据已持久化。
- 表单内容为空时阻止保存，并在弹窗内显示校验提示。

## 验证

- 纯函数测试覆盖：名称可选、内容必填、名称与内容搜索、英文大小写、编辑和删除。
- 本地状态测试覆盖：提示词库版本化读写及异常回退。
- 页面契约测试确认：每个 P 的渲染块包含提示词库入口，弹窗获得目标 P，空内容直接填入，已有内容先确认再替换。
- 运行提示词库相关测试、完整测试套件和生产构建。

## 验收标准

1. 任一 P 页面都能打开提示词库，弹窗显示正确的目标 P。
2. 用户能新增名称可选、内容必填的提示词，刷新页面后数据仍存在。
3. 用户能用名称或内容关键词搜索提示词。
4. 用户能编辑和确认删除提示词。
5. 用户能一键把提示词填入目标 P；目标框已有内容时必须确认替换，空白时无需确认。
6. 本地存储失败会明确提示，且不会导致当前页面操作中断。
