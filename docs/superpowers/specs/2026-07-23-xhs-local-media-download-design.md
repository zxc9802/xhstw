# 小红书抓取媒体本机下载设计

## 状态

- 日期：2026-07-23
- 状态：设计已由用户逐段确认，等待书面规格复核
- 适用范围：通过本机浏览器扩展新增到“爆款选题库”的小红书抓取结果

## 目标

抓取小红书笔记时，不再只保存可能过期、受防盗链限制或刷新后失效的远程媒体 URL。扩展必须下载笔记中的全部正文图片、视频文件和视频封面，将真实文件仅保存在当前电脑的浏览器存储中，并继续在爆款选题卡片现有媒体区域展示。

本功能保留现有选题库的产品语义：媒体属于抓取选题，而不是左侧导航“素材库”中的独立素材。网页服务器不接收、不代理、不持久化这些媒体文件。

## 已确认的需求

- 下载每篇新抓取笔记中的全部正文图片。
- 下载视频笔记中的视频文件和视频封面。
- 文件只保存在当前电脑、当前浏览器配置中。
- 媒体继续显示在爆款选题卡片现有媒体区域。
- 不在左侧“素材库”列表中创建条目。
- 单个媒体下载失败时，保留已经成功的媒体和选题文案，继续抓取下一篇。
- 点击选题“删除”时，同步删除该选题的本地媒体文件。
- “保留/取消保留”不影响本地媒体。
- 相同笔记或相同媒体再次抓取时复用已经完成的本地文件。
- 本设计只作用于实施后新抓取的结果，不自动回填历史选题中的远程媒体。

## 非目标

- 不把小红书媒体上传到应用服务器、对象存储或共享数据库。
- 不把抓取媒体写入左侧“素材库”或“产品资料库”。
- 不调用服务器媒体代理作为下载兜底。
- 不把文件保存到用户的“下载”目录后再尝试使用 `file://` 地址展示。
- 不自动回溯下载现有选题中的媒体。
- 不改变现有关键词、筛选、排序、保留、拒绝和去重规则。

## 现状与问题

当前扩展从小红书详情 DOM 中读取图片或视频的 `currentSrc`、`src` 和视频 `poster`，将远程 HTTPS URL 放入 `Topic.media`。选题页把这些 URL 写入 `localStorage`，并在卡片媒体区域直接用 `<img>` 或 `<video>` 展示。

当前流程没有下载真实文件，也没有将抓取媒体写入 IndexedDB。小红书 CDN URL 可能因防盗链、签名、登录状态或时效失效，导致卡片显示“暂无采集图片”、图片损坏或视频无法播放。

现有左侧“素材库”使用另一套元数据和 IndexedDB Blob 存储。抓取选题不调用该模块，因此本设计不改变素材库列表。

## 方案比较

### 方案一：扩展下载并分块传给网页，网页写入本机 IndexedDB（采用）

扩展后台具备受限的跨域请求权限，负责请求小红书官方媒体域名。响应体按固定大小分块，通过扩展端口和网站内容脚本传到选题页。选题页逐块写入专用 IndexedDB，并用本地 Blob URL 展示。

优点：媒体不经过服务器；能保留当前浏览器登录和网络环境；刷新后仍可恢复；可以做任务绑定、校验、去重和失败清理。

代价：需要升级扩展协议，增加分块确认和本地文件生命周期管理。

### 方案二：服务器媒体代理

网页通过同源 API 让服务器下载小红书媒体，再写入浏览器存储。实现路径较短，但媒体会经过服务器，增加带宽、超时、存储和 SSRF 风险，也违反“只保存在当前电脑”的要求，因此不采用。

### 方案三：Chrome 下载目录

扩展使用下载权限把文件保存到硬盘目录。大文件传输效率较高，但网页不能稳定、持久地访问任意本地文件，刷新后无法保证卡片播放，且需要额外高权限，因此不采用。

## 总体架构

```text
小红书详情页内容脚本
  -> 返回正文、图片 URL、视频 URL、视频封面 URL
扩展后台 Service Worker
  -> 校验官方媒体域名和媒体响应
  -> 读取响应流并生成固定大小分块
网站域名内容脚本
  -> 校验任务、媒体、分块序号
爆款选题页面
  -> 逐块写入专用 IndexedDB
  -> 写入完成清单和 Topic 本地媒体索引
  -> 从 IndexedDB 恢复 Blob URL
  -> 在现有卡片媒体区域展示
```

扩展负责跨域访问和下载编排；网页负责本机持久化、页面状态和 UI。服务器不参与媒体数据路径。

## 组件职责

### 小红书内容脚本

- 继续只解析可见详情区域中的正文媒体。
- 对视频同时返回视频 URL 和 `poster` 封面 URL。
- 排除头像、评论、导航、图标和其他非正文媒体。
- 保留媒体在笔记中的稳定顺序。
- 不在页面上下文中下载大文件。

### 扩展后台 Service Worker

- 为每个已确认有效的选题生成下载清单。
- 只允许 HTTPS 且主机属于小红书或其官方 CDN 白名单。
- 使用流式 `fetch` 下载媒体，不一次性读取完整视频。
- 将原始字节转换为有大小上限的 Base64 分块，经现有 `Port` 传输。
- 每发送一个分块后等待网页确认，再继续发送，形成背压，防止端口和内存被大视频淹没。
- 图片、视频和视频封面分别作为独立本地文件处理。
- 每个媒体最多重试两次；媒体失败只增加失败计数，不终止整批任务。
- 登录失效、验证码和访问频繁继续作为整批阻断错误。

### 网站域名内容脚本

- 继续作为网站页面与扩展后台之间的固定消息桥。
- 只转发通过协议校验的下载开始、分块、完成、失败和确认消息。
- 不执行网站传入的任意代码。
- 页面关闭或端口断开时终止当前下载并触发未完成分块清理。

### 爆款选题页面

- 接收媒体下载事件并逐块写入本机 IndexedDB。
- 维护当前任务的媒体进度、成功数和失败数。
- 最终结果到达后，将本地媒体索引合并到 `Topic` 数据并继续使用现有 `localStorage` 保存元数据。
- 页面加载时从 IndexedDB 恢复媒体 Blob URL。
- 卡片优先展示本地媒体；不以远程 URL 作为已下载成功媒体的展示来源。
- 页面卸载或媒体更新时回收旧 Blob URL。

## 本机存储设计

抓取媒体使用独立数据库，避免与左侧素材库的 `content-production-studio-assets` 数据和升级版本互相影响。

```text
数据库：content-production-studio-xhs-topic-media
对象仓库：manifests
对象仓库：chunks
```

### 媒体清单

```ts
type TopicMediaManifest = {
  assetKey: string;
  topicKey: string;
  mediaRole: "image" | "video" | "poster";
  sourceUrl: string;
  mimeType: string;
  size: number;
  chunkCount: number;
  status: "complete";
  createdAt: string;
};
```

只有所有分块成功写入后才创建 `complete` 清单。清单不存在即表示该文件不可用；不保留“半完成”清单。

### 分块记录

分块键由 `assetKey + chunkIndex` 组成，值保存为 Blob 或字节数组。页面恢复媒体时按序读取分块并构造一个 Blob URL，不在数据库中再复制一份完整文件。

`assetKey` 由标准化笔记 ID、媒体角色、媒体顺序和标准化源 URL 摘要生成。该键在同一笔记媒体未变化时保持稳定，用于去重和复用。

### Topic 元数据扩展

选题的媒体项在保留原始 URL 用于去重和诊断的同时增加本地索引：

```ts
type TopicMedia = {
  type: "image" | "video";
  url: string;
  name?: string;
  posterUrl?: string;
  localAssetKey?: string;
  posterLocalAssetKey?: string;
  mimeType?: string;
  size?: number;
};
```

`localAssetKey` 只在真实文件完整保存后写入。失败媒体不得伪造本地索引。

## 扩展协议升级

协议版本升级，旧扩展必须被网页识别为不兼容并提示重新安装或加载新版扩展。

扩展到页面新增固定消息类型：

- `media:start`：声明媒体键、角色、类型、源 URL 和可用的响应元数据。
- `media:chunk`：包含媒体键、连续分块序号、Base64 数据和分块长度。
- `media:complete`：包含最终字节数、分块数和媒体类型。
- `media:error`：包含媒体键、可公开错误码和简短说明。

页面到扩展新增：

- `media:ready`：页面检查本地存储后允许开始下载。
- `media:skip`：完整清单已存在，扩展复用现有文件。
- `media:ack`：指定分块已经持久化，可以发送下一块。
- `media:abort`：页面写入失败、空间不足或任务已取消。

每条消息必须匹配活动任务 ID、媒体键和预期序号。未知字段、超长字段、乱序分块、重复完成和错误方向的消息一律拒绝。

## 数据流程

1. 用户提交抓取任务，扩展按现有流程搜索、筛选并点击详情。
2. 内容脚本解析有效详情，返回完整正文媒体清单。
3. 后台构建 Topic 和每个媒体的稳定 `assetKey`。
4. 后台发送 `media:start`；页面检查是否已有完整清单。
5. 已存在时页面回复 `media:skip`，后台不重复下载。
6. 不存在时页面回复 `media:ready`，后台开始受限流式下载。
7. 每个分块经 `media:chunk -> IndexedDB 写入 -> media:ack` 顺序完成。
8. 媒体完成后页面校验总大小和分块数，写入完整清单。
9. 下载失败时页面删除该媒体的临时分块，后台继续下一个媒体或下一篇。
10. 批次完成后扩展返回带本地索引的 Topic 列表和媒体成功/失败统计。
11. 选题页合并新 Topic，持久化元数据并恢复本地 Blob URL。

## 用户界面

- 卡片媒体区保持现有布局和横向展示方式。
- 图片从本地 Blob URL 展示。
- 视频在卡片中优先显示本地封面；点击后在现有预览弹层使用本地视频 Blob URL 播放。
- 视频没有可用封面时显示视频占位图；不因封面失败丢弃已成功的视频。
- 顶部反馈显示当前阶段，例如“正在下载第 1/3 篇：视频 2/4”。
- 批次完成后显示选题数、媒体成功数和媒体失败数。
- 部分媒体失败时保留选题和已成功媒体，不把整批显示为失败。
- 不在左侧“素材库”生成任何条目。

## 容量与生命周期

- 下载前页面调用浏览器存储估算；可请求持久化存储，但不保证浏览器一定批准。
- 不设置任意文件大小上限；实际限制由可用浏览器存储空间和媒体响应决定。
- IndexedDB 写入出现配额错误时，中止当前媒体并提示“本机存储空间不足”，已经完成的媒体继续保留。
- 任务取消、页面关闭、扩展断开或下载失败时，清理该任务尚未完成的分块。
- 点击选题“删除”时删除该选题引用的本地清单和全部分块，并回收 Blob URL。
- “保留/取消保留”只改变选题状态，不移动或删除媒体。
- 同一 `assetKey` 的完整媒体被多个状态记录引用时，删除前应确认没有仍显示的选题引用；当前选题模型按标准化笔记 ID 去重，因此正常流程中只有一个有效引用。

## 安全边界

- 扩展仅增加经过枚举的官方媒体主机权限，不申请 Cookie、历史记录、全站访问或用户下载目录权限。
- 下载 URL 必须使用 HTTPS，禁止重定向到白名单外主机。
- 响应 `Content-Type` 必须属于 `image/*` 或 `video/*`；不保存 HTML、脚本、JSON 或可执行内容。
- 源 URL、媒体键、MIME、大小、分块长度和错误消息均有协议上限。
- Base64 解码后的实际字节数必须与声明长度一致。
- 完成时校验累计字节数和分块数；不完整文件永远不进入可展示状态。
- 网站来源、消息方向、协议版本、任务 ID 和媒体 ID 必须全部匹配。
- 媒体不经过应用服务器，服务器日志和数据库中不出现媒体字节。

## 错误处理

| 场景 | 行为 |
|---|---|
| 单张图片下载失败 | 清理该图片临时分块，记录失败并继续 |
| 视频下载失败 | 保留已成功封面和选题，记录失败并继续 |
| 视频封面下载失败 | 保留视频，用占位图展示，记录失败并继续 |
| 响应主机或类型不允许 | 拒绝该媒体，记录安全校验失败并继续 |
| 分块乱序或校验失败 | 中止该媒体、清理临时分块，不接受后续分块 |
| IndexedDB 配额不足 | 中止当前及后续媒体下载，保留已完成文件和选题 |
| 网站页面关闭或扩展断开 | 取消任务并清理未完成分块 |
| 登录、验证码、访问频繁 | 沿用现有整批阻断和冷却策略 |
| 老版本扩展连接 | 禁止开始抓取并明确提示升级 |

## 部署与升级

这不是只改扩展脚本的功能。网页协议、IndexedDB 管理、Topic 本地索引和卡片恢复逻辑都需要更新，因此必须：

1. 部署新的网页项目版本。
2. 生成新的解压扩展目录和 ZIP 包。
3. 在 Chrome/Edge 扩展管理页重新加载新版扩展。
4. 刷新生产网站，确认网页报告的新协议版本兼容。

网页和扩展任一侧未升级时都不得开始媒体下载，避免协议混用产生损坏文件。

## 测试策略

### 单元测试

- 官方媒体 URL、重定向和 MIME 白名单校验。
- 稳定 `assetKey` 生成和相同媒体去重。
- 分块编码、解码、长度校验和序号校验。
- 完整清单只在全部分块完成后创建。
- 页面刷新后从分块恢复 Blob 和媒体顺序。
- 视频与封面使用不同本地键并正确关联。
- 单个媒体失败继续后续媒体。
- 删除选题递归清理清单和分块。
- 旧版 Topic 没有本地键时保持原有兼容展示。

### 协议与集成测试

- `media:start -> ready -> chunk/ack -> complete` 完整握手。
- 已有完整媒体返回 `media:skip`，不发起网络下载。
- 错误任务 ID、错误媒体键、乱序分块和未知字段被拒绝。
- 页面写入失败返回 `media:abort`，扩展停止该媒体。
- 多图片加一个视频和一个封面的混合笔记保持顺序。
- 部分失败的批次仍返回有效 Topic 和准确统计。
- 协议升级后旧扩展被识别为不兼容。

### 真实浏览器验证

- 抓取一篇多图笔记，断网并刷新生产页，全部图片仍显示。
- 抓取一篇视频笔记，断网并刷新生产页，封面仍显示且视频可播放。
- 人为制造一个媒体下载失败，确认其他媒体和下一篇继续。
- 重复抓取相同笔记，确认 IndexedDB 占用不重复增长。
- 删除选题后确认清单、分块和 Blob URL 被清理。
- 检查服务器请求日志，确认媒体字节没有经过服务器。

## 验收标准

1. 新抓取图文笔记的全部正文图片以真实文件保存在当前浏览器中。
2. 新抓取视频笔记的视频文件和视频封面以真实文件保存在当前浏览器中。
3. 断网刷新后，成功下载的媒体仍能在爆款选题卡片和预览弹层中展示或播放。
4. 单个媒体失败不终止整批任务，页面显示准确的成功和失败数量。
5. 相同媒体不会重复下载或重复占用存储。
6. 删除选题会清理对应本地文件；保留状态切换不会影响文件。
7. 左侧“素材库”不出现抓取媒体条目。
8. 应用服务器不下载、接收或持久化小红书媒体字节。
9. 老版本扩展不能与新网页协议混用，并收到明确升级提示。
10. 现有选题筛选、排序、保留、拒绝、删除和去重功能无回归。
