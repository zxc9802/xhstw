# 马来西亚 TikTok 爆款视频工作流

用户要求在现有内容工作台新增马来西亚 TikTok 视频抓取、拆解、文案改写和拍摄脚本生成，并明确无法完成的功能。

新增独立 `/tiktok` 页面和导航入口，沿用现有组件与主站积分流程，不改动原图文流程。按用户最新确认，TikTok 创作使用独立的 OpenLux `gemini-3.8-flash` 配置，挂车状态不采集、不展示、不参与筛选。默认筛选粉丝 ≤ 20,000、播放 ≥ 50,000、近 7 天、播放/粉丝比至少 3 倍且上不封顶、内容类目不限；支持近 3 天、严格 3–5 倍和至少 5 倍。播放/粉丝比不是粉丝增长率。

数据入口为 TikHub App V3 关键词搜索或公开视频链接详情，以及 JSON/CSV 导入。TikHub 搜索不支持市场筛选，按账号国家接口核验 MY；仅为关键词样本，无法保证全站覆盖或满足条件数量。分页按返回 cursor 继续，限制单批请求规模并检测重复。接口无密钥、HTTP/业务错误均显式报错，不生成模拟数据。

标准记录保留精确字符串视频 ID、原链接、说明、作者、粉丝、播放、发布时间、国家、挂车状态、类目、逐字稿、采集时间、来源和原始证据。缺失值保留 null。已知不符合优先排除；没有不符合但缺少必要数据则待核实。0 粉丝不能计算倍数。仅明确字段支持国家、挂车、类目判断，不从语言或关键词推断。

原片处理链路从身份一致的 TikHub 详情读取媒体地址，下载后验证视频与音频轨道、准确时长及完整解码，压缩整段上传给 OpenLux。输出原语言人声转录、连续覆盖完整时长的原片画面/声音/字幕/剪辑时间轴及节奏分析，保存来源和模型输入文件哈希，精确删除临时媒体。单条原片限 180 秒/64 MiB，上传副本限 18 MiB；识别文字、细节和时间戳需要人工核对。无可辨人声时返回真实空逐字稿，失败不冒充成功。

AI 接收服务端保存并绑定来源的原片分析，及用户修正的逐字稿/人工观察，生成结构化创作拆解、原创改写和可执行新拍分镜；旧文字功能仍可用并明确标注依据。支持中文、英语、马来语和时长、产品事实、拍摄要求。拍摄约束独立于不可信参考资料，严格遵守允许的人数、设备和场景。原片价格、优惠、地点及数量等是原片声称，不自动作为当前商品事实；新文案的具体事实只取用户确认的 productFacts。缺少配置或响应结构错误不回退模拟成功。

记录、原片分析和生成结果保存在当前浏览器，支持 JSON 导出并恢复完整有效备份；拍摄包保存生成时的原片分析快照，支持 Markdown 导出并记录生成模型。服务端分析缓存供重新生成时验证来源；跨服务器迁移后需要重新分析。API 密钥只在服务端。页面清晰说明识别准确度及资源限制，尚未实现全量监控、自动拍摄剪辑发布及效果保证。

验证：阈值边界、缺失/零/未来日期、精确 ID、导入去重、CSV 转义、国家与 sec UID 身份错配、业务错误、分页重复、凭据缺失、AI 格式、语言及拍摄约束、图文作品跳过、完整备份恢复；运行类型检查、全量测试、构建和浏览器交互检查。已使用用户授权的密钥进行真实 TikHub 与 OpenLux 服务验收，证据与范围在 `outputs/tiktok-final-verification/`。
