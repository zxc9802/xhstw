# 用户本机浏览器抓取小红书设计

## 状态

- 日期：2026-07-22
- 状态：设计已由用户逐段确认，等待书面规格复核
- 适用范围：爆款选题库的小红书公开内容抓取

## 目标

将小红书页面访问从服务器共享 Chrome 迁移到每位使用者自己的 Chrome 或 Edge。用户在网站点击一次“开始抓取”后，由浏览器扩展在其本机自动打开小红书、执行筛选和解析，再把结构化结果返回当前网站页面。

迁移后，小红书访问使用该用户本机的网络出口、浏览器环境和既有登录态。服务器只提供网站页面和后续业务能力，不登录小红书、不保存小红书 Cookie，也不直接访问小红书搜索页、详情页或媒体资源。

## 非目标

- 不建设服务器抓取兜底。
- 不建设云端任务队列或无人值守定时抓取。
- 不在本次改造中把不同用户的选题库改成共享数据库。
- 不在第一版发布 Chrome Web Store 或 Edge Add-ons 商店版本。
- 不上传或同步用户的小红书 Cookie、账号信息、浏览历史或完整页面内容。

## 当前行为与问题

当前选题页面调用 `POST /api/topics/opencli-xhs`，由服务器上的 OpenCLI 适配器打开小红书搜索页和多个详情页。多人使用时，请求会集中到同一个服务器出口和共享 Chrome，前端的 `collecting` 状态只能阻止当前标签页重复点击，不能限制其他用户。

选题、拒绝列表、删除列表和关键词目前保存在各自浏览器的 `localStorage`。本次改造保留这一行为，每位用户继续只看到自己的抓取结果。

## 方案选择

采用自定义 Manifest V3 浏览器扩展作为网站与用户本机小红书页面之间的桥梁。

未采用的方案：

1. OpenCLI 加本地 Browser Bridge：能够复用现有调用方式，但每台电脑还需安装和维护本地命令行服务，交付和排错成本更高。
2. 扩展轮询服务器任务队列：可以在网站关闭后继续运行，但引入了云端任务状态、用户绑定和无人值守抓取，本次没有此需求。

## 总体架构

```text
网站选题页面
  -> 网站域名内容脚本
  -> 扩展后台 Service Worker
  -> 用户本机的小红书标签页
  -> 小红书域名内容脚本
  -> 扩展后台 Service Worker
  -> 网站域名内容脚本
  -> 网站选题页面和本机 localStorage
```

网站和扩展之间直接在用户浏览器内通信。抓取任务和结果不需要经过服务器任务队列。

## 组件职责

### 网站页面

- 检测扩展是否已安装并显示“本机抓取已连接”或“需要安装扩展”。
- 保留现有关键词、数量、时间范围、内容类型、排序方式和去重参数。
- 为每次抓取生成不可复用的任务 ID。
- 发送白名单任务参数，接收进度、结果和错误状态。
- 将返回的 `Topic` 数据合并到现有选题列表，并继续使用现有 `localStorage` 保存逻辑。
- 扩展未安装或不可用时禁止开始抓取，不调用服务器抓取作为后备方案。

### 网站域名内容脚本

- 只在配置好的网站生产域名和开发域名注入。
- 完成网站页面与扩展后台之间的握手和消息转发。
- 校验消息来源、任务 ID、消息类型和字段结构。
- 不执行网站传来的任意代码。

### 扩展后台 Service Worker

- 每个浏览器同时只允许一个抓取任务。
- 管理任务状态、超时、冷却时间和标签页生命周期。
- 自动创建并切换到专用小红书标签页。
- 把固定格式的任务参数传给小红书内容脚本。
- 抓取成功后关闭专用标签页并切回发起任务的网站标签页。
- 遇到需要人工处理的问题时保留小红书标签页，同时停止任务。

### 小红书域名内容脚本

- 只在 `https://www.xiaohongshu.com/*` 下运行。
- 执行固定实现的搜索、筛选、滚动、列表解析和详情解析。
- 复用现有适配器中已经验证的页面解析规则，但将其整理为扩展内可测试的解析模块。
- 检测登录失效、验证码、安全限制、页面加载超时和页面结构不匹配。
- 只返回业务需要的结构化字段，不返回 Cookie 或整页 HTML。

## 任务协议

网站只能传递以下任务字段：

```ts
type XhsCollectTask = {
  requestId: string;
  queries: string[];
  limitPerQuery: number;
  mediaType: "全部" | "图文" | "视频";
  dateRange: "全部" | "一天内" | "一周内" | "半年内";
  sortBy: "浏览量" | "点赞量" | "评论量" | "收藏量";
  existingUrls: string[];
};
```

第一版限制每个任务最多 2 个关键词、每个关键词最多 5 篇。扩展拒绝未知字段、超限参数、重复任务 ID 和非许可网站域名发起的任务。

任务状态固定为：

```text
idle -> opening -> searching -> enriching -> completed
                                     |-> blocked
                                     |-> failed
```

进度消息至少包含任务 ID、当前关键词、当前阶段、已完成数量和目标数量。结果消息继续使用现有 `Topic` 结构，减少网站侧改动。

## 自动运行与用户体验

1. 用户首次安装扩展，并在自己的浏览器中正常登录小红书。
2. 网站确认扩展在线后启用“开始抓取”。
3. 用户点击一次后，扩展自动打开一个可见的小红书标签页并切换过去。
4. 扩展依次完成搜索、页面筛选、滚动和详情解析，网站同步显示进度。
5. 成功后扩展关闭专用标签页，切回网站，网站显示并保存结果。
6. 登录失效、验证码或安全限制需要人工处理时，扩展保留小红书标签页，网站显示明确原因。

可见标签页是第一版的固定行为。它避免后台标签页计时器限速，也让用户知道自己的浏览器正在访问什么页面。

## 访问节奏与风控保护

- 每台电脑同时只运行一个任务。
- 详情页之间至少间隔 4 秒，关键词之间至少间隔 15 秒。
- 不对失败页面自动快速重试。
- 检测到“300013”“访问频繁”或等价安全限制时立即停止，并在本机记录 60 分钟冷却时间。
- 冷却期间网站仍可使用其他功能，但扩展拒绝新的小红书抓取任务并显示剩余冷却时间。
- 这些限制用于减少访问压力，不能保证平台一定不触发安全限制。

## 权限与安全边界

- 扩展仅声明网站域名和 `xiaohongshu.com` 的必要主机权限。
- 不申请 `cookies`、`history`、下载目录或全站访问权限。
- 使用固定内容脚本，不允许服务器或网站传递任意 JavaScript 给扩展执行。
- 所有消息都校验来源标签页、来源域名、任务 ID 和字段结构。
- 任务完成、失败或取消后清除内存中的任务参数和抓取结果。
- 扩展本地存储只保存版本信息、活动任务状态和冷却截止时间。
- 生产环境禁用现有服务器抓取入口；扩展失败时只提示修复扩展或用户登录状态，不自动切回服务器。

## 错误处理

| 场景 | 行为 |
|---|---|
| 扩展未安装或版本不兼容 | 禁用抓取按钮并显示安装或升级提示 |
| 浏览器已有任务运行 | 拒绝新任务并显示当前进度 |
| 小红书未登录 | 停止任务、保留标签页并提示用户登录 |
| 验证码或人工验证 | 停止任务、保留标签页并提示人工处理 |
| 300013 或访问频繁 | 停止任务、保留标签页并进入 60 分钟冷却 |
| 页面加载超时 | 停止当前任务，返回具体阶段和超时原因，不自动重试 |
| 页面结构变化 | 返回“页面结构暂不兼容”，保存最小诊断信息，不返回整页内容 |
| 网站标签页被关闭 | 取消任务并关闭由扩展创建的专用标签页 |
| 用户手动取消 | 立即停止解析、关闭专用标签页并清理任务状态 |

## 服务器与现有代码的变化边界

- 选题页面从调用 `/api/topics/opencli-xhs` 改为调用本机扩展桥接模块。
- 现有服务器 OpenCLI 解析逻辑只作为迁移参考，不再承担生产小红书抓取。
- 生产服务器抓取 API 应返回明确的已禁用响应，避免旧页面或外部请求继续触发服务器访问。
- 现有选题列表、去重、保留、拒绝、删除和 `localStorage` 数据结构保持不变。
- 扩展返回远程素材 URL 后，网站由用户浏览器直接展示；扩展来源的素材不得再经过现有服务器媒体代理，确保搜索页、详情页和媒体资源都不由服务器访问。

## 安装与交付

第一版交付一个可解压的 Chrome/Edge 扩展目录和简短安装说明。内部用户通过浏览器扩展管理页开启开发者模式并“加载已解压的扩展”。网站提供扩展状态检测和版本提示。

第一版不做商店发布和静默自动更新。升级时提供新的版本包，扩展版本与网站要求的最低协议版本不匹配时，网站禁止抓取并提示升级。

## 测试策略

### 单元测试

- 任务参数白名单、数量上限和任务 ID 校验。
- 状态机合法转换、单任务锁和 60 分钟冷却。
- URL 归一化、去重和现有 `Topic` 字段映射。
- 使用固定 HTML 样本测试搜索卡片和详情页解析。
- 验证登录失效、验证码、300013 和结构变化识别。

### 扩展集成测试

- 网站与扩展握手、版本检查、任务发送、进度和结果返回。
- 自动创建标签页、切换、成功关闭、失败保留和返回网站。
- 网站关闭、用户取消、标签页被手动关闭时的清理行为。
- 确认扩展清单不包含 Cookie 和浏览历史权限。

### 端到端验证

- 使用安装了扩展且已登录小红书的 Chrome 和 Edge 各完成一次真实抓取。
- 两台电脑同时抓取不同关键词，确认使用各自浏览器、任务不串线、结果互不共享。
- 观察服务器访问日志，确认抓取期间服务器没有访问小红书搜索页、详情页和媒体地址。
- 验证扩展未安装、未登录、冷却中和页面异常时不会回退到服务器抓取。

## 验收标准

1. 用户只点击一次网站“开始抓取”即可完成整个本机抓取流程。
2. 抓取期间使用用户本机浏览器、网络出口和登录态。
3. 服务器不登录小红书、不接收 Cookie，也不直接请求小红书抓取页面。
4. 两名用户同时操作时任务和结果完全隔离。
5. 结果继续保存在各自浏览器的现有选题库中。
6. 所有已定义异常都能停止任务、清理状态并显示明确原因。
7. 300013 等安全限制不会触发自动重试或服务器兜底。
8. 现有选题保留、删除、拒绝和去重功能没有回归。
