# 小红书扩展详情点击修复设计

## 背景

`0.1.0` 扩展能够在登录用户的浏览器中打开小红书搜索页并返回搜索卡片，但它没有真实点击卡片。后台脚本将搜索结果的 `/search_result/{noteId}` 链接改写为 `/explore/{noteId}` 后直接导航，详情脚本又把任意 `.title`、`img` 或 `video` 当成详情已加载。因此，小红书返回“当前笔记暂时无法浏览”时，扩展会把提示文字误当笔记标题、把页面装饰图片误当正文媒体，并将无效结果报告为成功。

## 目标

- 搜索后在当前小红书搜索页真实点击目标卡片。
- 只在可见的详情区域内等待和解析笔记数据。
- 不可浏览、已删除或无权限的单条笔记跳过并继续抓取后续结果。
- 登录失效、验证码和访问频繁继续作为整批阻断错误处理，并保留任务页供人工处理。
- 只有有效详情才能写入网站本地选题库。
- 修复版本打包为 `0.1.1`，不覆盖现有 `0.1.0` 交付物。

## 非目标

- 不调整网站选题库的筛选、保留或删除交互。
- 不增加服务器端抓取后备路径。
- 不扩大扩展权限或允许网站下发任意脚本。
- 不重构无关的图片生成、飞书同步或其他内容生产流程。

## 方案比较

### 方案一：搜索页真实点击卡片（采用）

内容脚本根据笔记 ID 在当前搜索页定位卡片链接，调用浏览器原生点击，等待小红书自己的详情弹层出现后解析。它与人工访问路径一致，能够保留搜索页已有的客户端上下文、临时令牌和页面状态。

### 方案二：保留原始 `/search_result` 链接直接导航

该方案改动更小，但仍绕过搜索卡片的客户端点击流程，无法保证小红书的弹层状态和临时上下文被正确创建，因此不采用。

### 方案三：每条详情单独打开新标签页

该方案隔离性更强，但标签页切换更多、抓取更慢，也更容易造成密集访问，不符合当前每批最多十条的顺序抓取设计，因此不采用。

## 数据流

1. 后台脚本打开关键词搜索页，并让内容脚本应用筛选、解析最多五个候选卡片。
2. 搜索结果继续返回标题、作者、互动量、封面、原始链接和笔记 ID。
3. 后台脚本向同一搜索页发送详情命令，包含期望标题和目标笔记链接。
4. 内容脚本按笔记 ID 定位目标卡片链接并真实点击。
5. 内容脚本等待以下三类互斥结果之一：
   - 可见且字段有效的详情区域；
   - 单条不可用提示；
   - 登录、验证码或访问频繁等整批阻断状态。
6. 有效详情在详情区域内解析，然后关闭弹层并返回结构化结果。
7. 单条不可用返回可跳过状态，后台脚本继续同一关键词的下一条候选。
8. 整批阻断状态沿用现有失败处理；任务页保留，网站显示对应错误。
9. 后台脚本只把有效详情交给 `buildTopic`，完成后关闭任务标签页并回到来源网站。

## 详情有效性

详情必须满足以下条件才算成功：

- 存在非空标题，且标题不是“当前笔记暂时无法浏览”等错误提示；
- 正文、作者、互动量或正文媒体至少有一项有效；
- 解析范围来自可见详情区域，而不是导航栏、搜索卡片、评论头像或页面装饰区域。

搜索卡片封面只在详情已被确认有效、但详情正文媒体为空时作为媒体回退。它不能单独把无效详情变成成功结果。

## 错误处理

单条可跳过状态包括“当前笔记暂时无法浏览”、笔记已删除和无权限查看。后台脚本不创建选题，不增加完成数量，并继续后续候选。任务结果消息需要包含成功条数和跳过条数。

登录失效、验证码和访问频繁仍然停止整批任务。访问频繁继续触发当前浏览器的 60 分钟冷却；这些状态下不自动关闭小红书任务页。

如果点击目标卡片失败、详情弹层超时或页面结构已变化，任务返回明确错误，不把搜索卡片拼装成假详情。

## 测试

- 收集器测试：不可浏览页不能产生成功详情；全页面无关 `.title` 和图片不能满足详情有效性。
- 内容动作测试：详情命令必须包含目标链接；脚本必须按笔记 ID 点击唯一卡片并等待详情区域。
- 后台编排测试：单条不可用会跳过并继续；整批阻断状态仍会停止任务。
- 打包测试：`0.1.1` 包含修复后的脚本、正确生产域名和 `manifest.json`。
- 真实浏览器验证：在同一登录浏览器内用一个关键词抓取一条，确认出现搜索页、卡片点击、详情弹层、有效字段回传和任务页关闭；选题库不得再新增“当前笔记暂时无法浏览”卡片。

## 交付

交付 `exports/xhs-browser-extension-0.1.1.zip` 及对应解压目录。用户需要在扩展管理页移除或停用 `0.1.0`，加载 `0.1.1` 解压目录，再刷新生产网站确认“本机抓取已连接”。
