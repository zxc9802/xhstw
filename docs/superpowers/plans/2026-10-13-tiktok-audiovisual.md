# TikTok 自动转录与原片音画拆解补全

纠正上一轮遗漏：用户原始要求包含视频拆解，不能仅交付文字资料分析。本次沿用已授权的 TikHub 和 OpenLux 服务，不更改挂车筛选决定。

已验证：本机 FFmpeg 可完整解码指定 TikTok 视频；原媒体直连失败，但当前 Windows 本地代理可下载。OpenLux 的 `video_url` 内容格式虽返回成功却描述了错误影片，不能使用。兼容接口的 `image_url` 承载 `data:video/mp4` 及原生 Gemini inlineData 均正确读取了原片音画；采用前者以沿用已配置地址。整段视频分析同时产出原语言转录与音画时间轴。

1. [x] 先写输出格式与错误媒体回归测试：错误时长、非媒体读取、缺失转录、时间轴缺口、无语音真实空值都须正确处理。
2. [x] 接入经过身份校验的 TikHub 原视频地址，当前代理、大小与时长限制、FFprobe 校验、完整 FFmpeg 解码、上传用压缩视频、来源与上传文件哈希。失败不包装成分析成功；临时媒体精确清理。
3. [x] 使用完整视频作为模型输入，返回转录、原片时间轴及视觉/剪辑/声音/节奏/字幕/行动引导分析，明确时间戳和识别的不确定性。流式显示处理阶段，保存绑定来源的分析结果。
4. [x] 页面增加自动分析入口、转录及原片音画结果展示；创作 API 仅从服务端验证过的分析记录读取媒体依据，历史文字功能保留。同步备份与拍摄包导出。
5. [x] 真实原片验证下载、转录、音画对应、改写、新拍脚本、刷新与导出；重跑相关测试、全量测试、应用类型检查及构建，更新原验收报告，区分之前文字测试与新音画测试。

边界：AI 转录、细小字幕、快速动作和时间戳可能有误，应人工核对；原片显示的价格/促销只代表原片内容，不能作为现在的商品事实。暂按单条 180 秒和 64 MiB 的资源限制处理，不能伪造超限影片的完整分析。
